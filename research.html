How the Privacy Core actually protects Vaultrix and Clozzy

Not a marketing claim — the real cryptographic design decisions behind our products: what's encrypted, what's derived vs. random, what never touches disk, and what we deliberately did not build (yet).

By the PrivoSafe engineering team · Updated September 2026 · ~6 min read

Vaultrix: an encrypted vault with no plaintext on disk

AES-256-GCM Argon2id CSPRNG Master Key In development

Vaultrix is a private vault for files, passwords, and photos. The design goal was simple to state and hard to get right: your password should never become your encryption key, and plaintext should never be written to storage at any point in the app's lifecycle.

Key architecture

  • Master Key A single random 256-bit key per vault, generated with a cryptographically secure random number generator — never derived from the password. This means a password change only re-wraps a small key blob, not every encrypted file.
  • Password wrapping Your password derives a key-encryption key via Argon2id (64 MB memory cost, 3 iterations, parallelism 2), which wraps — not replaces — the Master Key.
  • Encryption AES-256-GCM for both file contents and metadata (original filename, MIME type), with a fresh random nonce generated per operation. Nonces are never reused.
  • Key lifetime The Master Key lives only in memory (VaultSession) and is dropped when the app backgrounds or after an idle timeout (default 2 minutes).
  • Biometric unlock Wraps the Master Key with a separate, device-bound key gated behind the OS biometric prompt. The fingerprint or face scan itself never becomes cryptographic key material.

No plaintext, at any stage

On import, source bytes are read into memory, encrypted, and written to disk only as ciphertext — the file picker's temporary copy is deleted immediately after. On view, ciphertext is decrypted into an in-memory buffer handed to the UI and dropped when the screen closes. Deleted files are additionally shredded — overwritten with random bytes before removal — as defense-in-depth against filesystem-level undelete of the ciphertext.

Duress features

A Panic Wipe, gated behind a typed confirmation phrase, destroys the real vault's keys, metadata database, and every encrypted blob. A Decoy Vault lets a second password unlock a completely separate Master Key, database, and file space — unlockAny fails identically for a wrong password and a correct-but-wrong-vault password, so there is no timing or behavioral tell between the two.

Client-side signals, not a trust boundary

The in-app Security Center checks device integrity — root/jailbreak status, developer options, mock location, external storage — via the safe_device package, plus app posture like biometric enrollment and auto-lock, rolled into a protection score.

We're explicit about this internally and publicly: these are client-side hygiene signals a sufficiently privileged attacker on the device can spoof. They inform the user, they don't anchor the security model — the encryption above does that.

Clozzy: the same Privacy Core, applied to shared spaces

AES-256-GCM Argon2id Live

Clozzy is a private space for couples — messages, mood updates, photos, and daily notes shared between exactly two people. It runs on the same Privacy Core as Vaultrix: a random per-vault Master Key wrapped by an Argon2id-derived key from your password, with AES-256-GCM encrypting message content, media, and status updates before they ever leave the device.

Because the Master Key is generated and held client-side and only your password (or your partner's, for shared content) can unwrap it, PrivoSafe's own infrastructure is not in a position to read the contents of your space or hand it over in readable form — by design, not by policy promise.

Common questions

Straight answers

Does PrivoSafe store my password?

No. Your password is never stored anywhere. It's run through Argon2id to derive a key that wraps your Master Key — the password itself never leaves that one-way derivation.

What encryption does Vaultrix use?

AES-256-GCM for file contents and metadata, with a fresh random nonce per operation, protecting a CSPRNG-generated Master Key that's wrapped by an Argon2id-derived key from your password.

Does Vaultrix ever write unencrypted data to disk?

No. Plaintext exists only in memory during import and viewing. Everything persisted to disk is ciphertext, and temporary copies created by the OS file picker are deleted immediately.

What happens if I'm forced to unlock my vault under duress?

Panic Wipe destroys the real vault behind a typed confirmation phrase. Decoy Vault gives a second password its own separate vault with no detectable difference from a wrong password.

Is Clozzy end-to-end encrypted?

Yes — Clozzy shares Vaultrix's Privacy Core, so messages, photos, and status updates are encrypted client-side with AES-256-GCM under keys only you and your partner hold.

Can PrivoSafe read or sell my data?

PrivoSafe does not hold the keys needed to decrypt your content, and does not sell user data.

Found a security issue?

We'd rather hear from you first. If you find a vulnerability in Vaultrix, Clozzy, or the Privacy Core, please report it privately before any public disclosure.

We commit to acknowledging reports promptly and crediting researchers who report responsibly.
